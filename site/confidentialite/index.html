2. Objet de l'application

ACLO permet notamment de consulter les actualités, événements, absences annoncées des entraîneurs, informations relatives au personnel du club, membres Élite et performances sportives, ainsi que de recevoir des notifications push liées à la vie du club.

3. Données traitées

Selon les fonctionnalités utilisées, les catégories de données suivantes peuvent être traitées :

Données publiques relatives au club

  • nom et prénom de membres du personnel, responsables ou entraîneurs ;
  • fonction ou rôle dans le club ;
  • nom et prénom de certains athlètes Élite ;
  • niveau/grade sportif ;
  • performances sportives publiées ;
  • nom d'un entraîneur signalé absent et date de fin de l'absence ;
  • actualités et événements du club.

Données techniques

  • token de notification push Expo ;
  • plateforme de l'appareil (android ou ios) ;
  • date de dernière activité du token push ;
  • préférences de notifications associées à l’appareil (actualités, calendrier, entraînements, absences, équipements, athlètes Élites et notifications importantes) ;
  • journaux techniques et de sécurité ;
  • pour les comptes admin autorisés : adresse e-mail, identifiant de compte, date, type d’action, contenu concerné, identifiant de l’élément et noms des champs modifiés (sans conserver les anciennes/nouvelles valeurs dans le journal), ainsi que la trace d’un envoi push (sans conserver le titre ni le texte du message dans le journal) ;
  • adresse IP ou dérivé cryptographique de celle-ci lorsque cela est strictement nécessaire à la limitation des abus.

5. Mineurs

Le Royal ACLO accueille des mineurs. Une attention particulière doit donc être portée à leurs données.

L'application ne doit pas publier :

  • adresse privée ;
  • numéro de téléphone privé d'un mineur ;
  • date de naissance complète ;
  • donnée médicale ;
  • localisation en temps réel ;
  • information disciplinaire ou familiale ;
  • toute donnée qui ne serait pas nécessaire à la finalité poursuivie.

La publication d'informations relatives à des mineurs fait l'objet d'une appréciation spécifique et, lorsque la base juridique l'exige, d'une autorisation appropriée.

6. Notifications push

L'application peut demander l'autorisation d'envoyer des notifications. Cette autorisation peut être refusée ou retirée à tout moment dans les réglages Android ou iOS.

Le refus des notifications n'empêche pas l'accès aux principales informations disponibles dans l'application. Sur un nouvel appareil, toutes les catégories de notification sont activées par défaut. Dans l’onglet « Notifications », chaque personne peut ensuite activer ou désactiver les catégories proposées sur cet appareil, y compris « Notifications importantes ». Une catégorie désactivée n’est pas utilisée pour les envois ciblés de cette catégorie. Les préférences sont enregistrées avec le token de l’appareil et ne sont pas liées à un compte utilisateur de l’application. Leur activation par défaut sert aux notifications fonctionnelles et ne constitue pas un consentement au marketing direct. Si toutes les catégories sont désactivées, le token push de cet appareil est supprimé de la base. Pour les autres demandes relatives aux données, contacte le club à l’adresse indiquée dans cette politique.

Les tokens push sont utilisés uniquement afin d'acheminer les notifications du club. Des admins autorisés peuvent envoyer un titre et un message aux appareils inscrits. Le contenu est transmis à Expo, puis aux services Google/Apple nécessaires à la livraison. Il n’est pas conservé dans le journal d’audit ; celui-ci conserve uniquement l’action, l’acteur, la date et les champs concernés. Les tokens ne sont pas exposés publiquement. Les notifications importantes restent facultatives ; l’application ne doit pas être considérée comme un canal d’urgence ou de sécurité.

7. Destinataires et sous-traitants

Les données peuvent être traitées par les prestataires techniques nécessaires au service, notamment :

  • Supabase : base PostgreSQL et Edge Functions ;
  • Expo : infrastructure technique liée à l'application et aux notifications push ;
  • Google / Firebase Cloud Messaging : acheminement des notifications Android ;
  • Apple Push Notification service (APNs) : acheminement des notifications iOS ;
  • GitHub Pages : hébergement et distribution des pages publiques de confidentialité et d’assistance. GitHub et ses prestataires techniques peuvent traiter l’adresse IP, des informations de requête et des journaux techniques nécessaires à la livraison et à la sécurité ;
  • GitHub : hébergement du code source privé et automatisations de développement ;
  • jsDelivr : distribution du SDK Supabase utilisé par la page d’administration ; le navigateur transmet les métadonnées réseau usuelles (dont l’adresse IP) lors de son chargement.

Le club doit réexaminer cette liste à chaque ajout d'un SDK ou prestataire.

8. Hébergement et transferts internationaux

La base principale Supabase de l'application est configurée dans la région eu-west-3 (Paris, France). Les pages publiques de confidentialité et d’assistance sont hébergées sur GitHub Pages, avec l’adresse https://loouisdev.github.io/aclo.doc. GitHub et ses prestataires traitent les données réseau nécessaires à la transmission et à la sécurité des requêtes web, notamment l’adresse IP et les journaux techniques.

Certains fournisseurs techniques peuvent néanmoins traiter des données ou métadonnées en dehors de l'Espace économique européen. Lorsque le RGPD l'exige, les transferts doivent reposer sur un mécanisme reconnu, tel qu'une décision d'adéquation ou les clauses contractuelles types de la Commission européenne, accompagné si nécessaire de mesures complémentaires.

9. Durées de conservation

Les durées sont limitées à ce qui est nécessaire :

  • actualités : jusqu'à leur date d'expiration ou suppression ;
  • événements : suppression automatisée lorsque la date de fin est passée ;
  • absences d'entraîneurs : suppression automatisée après la date de fin ;
  • personnel du club : pendant l'exercice de la fonction, avec révision lors des changements ;
  • données Élite : révision au minimum à chaque saison ;
  • token push : suppression lorsqu’il est invalide, lorsque toutes les catégories sont désactivées dans l’app, ou après 365 jours sans activité ;
  • données de limitation d'abus : courte durée, actuellement 2 jours ;
  • historique des actions d’administration : 365 jours, puis suppression automatique.

10. Sécurité

Le club met notamment en œuvre :

  • HTTPS/TLS pour les communications ;
  • hébergement européen de la base principale ;
  • Row Level Security (RLS) ;
  • droits clients limités à la lecture des données publiques ;
  • les tables techniques de tokens push et de limitation de fréquence ne sont accessibles qu’aux fonctions serveur ;
  • espace d’administration sans formulaire d’inscription, réservé à une liste d’utilisateurs autorisés, avec mots de passe gérés par Supabase Auth. Le réglage Supabase doit désactiver les inscriptions publiques avant publication ;
  • journal d’audit limité aux métadonnées d’action et aux noms des champs modifiés, conservé 365 jours ;
  • fonctions d’administration protégées par JWT, liste d’autorisation et vérification AAL2 côté serveur ; l’enrôlement TOTP du compte administrateur reste à terminer avant son utilisation en production ;
  • séparation entre clés publiques client et secrets serveur ;
  • stockage des secrets serveur hors du code client ;
  • limitation de fréquence de certaines requêtes ;
  • suppression programmée de données devenues inutiles ;
  • contrôles automatisés des dépendances et secrets dans GitHub.

11. Droits des personnes

Dans les limites prévues par le RGPD, une personne peut notamment demander :

  • l'accès à ses données ;
  • leur rectification ;
  • leur effacement ;
  • la limitation du traitement ;
  • s'opposer à certains traitements ;
  • la portabilité lorsque les conditions sont réunies ;
  • retirer un consentement lorsque le traitement repose sur celui-ci.

Les demandes peuvent être adressées à secretariat.raclo@gmail.com. Le club y répond dans les délais prévus par le RGPD, en principe dans un délai d’un mois à compter de la réception ; une prolongation est possible dans les conditions prévues par le RGPD et doit être annoncée. Une preuve d'identité peut être demandée uniquement lorsqu'elle est nécessaire pour éviter une divulgation à un tiers.

13. Violation de données

Toute violation de données personnelles est documentée. Lorsqu'elle est susceptible d'engendrer un risque pour les droits et libertés des personnes, le club procède à la notification requise à l'APD dans les meilleurs délais et, si possible, dans les 72 heures après en avoir pris connaissance.

Lorsque la violation est susceptible d'engendrer un risque élevé, les personnes concernées sont également informées lorsque le RGPD l'exige.

14. Traceurs et publicité

La version actuelle d'ACLO n'a pas pour objectif d'effectuer du suivi publicitaire inter-applications.

Tout ajout futur d'un SDK publicitaire, d'un outil d'analyse non strictement nécessaire ou d'un mécanisme de suivi doit faire l'objet d'une nouvelle analyse de conformité, d'une mise à jour de la présente politique et, lorsque requis, d'un consentement préalable.

15. Modifications

Cette politique est réexaminée lorsque les fonctionnalités, les prestataires, les catégories de données ou les obligations légales changent.
